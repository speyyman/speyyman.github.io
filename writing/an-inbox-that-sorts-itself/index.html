An inbox that sorts itself

Note systems fail at filing. Mine stopped failing when I stopped filing at the moment of writing, and gave the sorting to agents that have to ask first.

Where it breaks

Most note systems fail in the same place. Not at search, not at sync, not at the app. At filing.

The pattern is always the same. You start with a clean set of folders. For a few weeks you file everything as it arrives, and it feels good. Then a thought turns up that belongs in two folders, or in none. You hesitate. You put it somewhere temporary. The temporary place fills up. One day you open the app and the backlog is the first thing you see, so you open it less. A month later it is a graveyard with a nice folder structure.

The reason is not discipline. Filing asks for a decision at the worst possible moment. When you capture something, you have the least information you will ever have about it. You don’t know yet whether the thought about the garden is a project, a reading note or a passing mood. The folders ask you to know. So each capture carries a small tax, paid up front, for a benefit that arrives later, if at all. Small taxes on something you do many times a day add up to not doing it.

So the system I use now, and have released as a starter kit, is built around one change. Nothing gets filed when it is written down.

One door

Everything new goes to one folder, 00 Inbox. A thought, a link, a pasted article, a screenshot. The capture template asks one question, what the note is about, and Escape skips even that. There are no folders to choose and no tags to remember.

The agent that captures follows the same rule. Its instructions say it plainly: never make the owner decide a category now. It checks for an existing note on the same thing, so I don’t end up with three notes about one idea, and then it writes the note in my words, without polishing them, and says where it went in one line. It does not ask a follow-up question about categories. That is the weekly review’s job.

There is one exception, and it is a useful one. Some things are not notes at all. “Call about the boards on Monday” needs a reminder, not a place in a folder. So the capture rule is a single question: does this need a reminder? If yes, it goes to a task app. If not, it goes to the Inbox. A task that belongs to a project goes to that project instead, because two copies of the same task always drift apart.

The rule of the vault is to capture anywhere and sort once a week, so never make the owner decide a category now.

Five questions, once a week

Sorting still happens. It just happens once a week, in a twenty-minute review with a timer, when I have the context the capture lacked. By then I know whether the garden thought turned into a plan.

Where a note goes is not a matter of taste. It is five questions, asked in order, stopping at the first yes. Does it have a finish line? Projects. Did I look it up? Research. Did it come from my own head? Mind. Is it an ongoing part of life? Life. Is it finished? Archive. If none fits, the note stays in the Inbox, and the rules say in so many words that this is a valid outcome. A note that can wait another week is not a failure of the system. It is the system working.

Fixed questions matter because they make sorting boring, and boring is fast. There is no taxonomy to maintain and no folder called Misc. Eight top-level folders, numbered so they sort the same way everywhere, and a Home page that shows only what needs attention.

Agents that ask

The part that took the filing off my plate is the agents. Not in the way the phrase usually suggests. Nothing runs in the background, watches the folder or edits notes overnight. Each agent is a skill: a short Markdown file of instructions that Claude Code follows when I type its name. There are eleven of them, one job each.

The inbox skill shows the difference. It reads every note in the Inbox in full, never deciding from the title. It searches the rest of the vault so duplicates get merged rather than filed twice. Then it shows one short table: note, destination, new type, a few words of reason. Merges and deletions are listed separately. Only after I say yes does it move anything, and it moves notes through Obsidian rather than behind its back, so every link that pointed at them still works.

Deleting needs its own yes, even after I have said “go”. That one rule is why I trust the rest. An agent that can be wrong is fine. An agent that can be wrong silently, and irreversibly, is not something I want near my notes.

The review itself works the same way. The weekly skill does the legwork, so I only decide. It summarises the week’s daily notes factually: what got done, the energy numbers and their average, anything that repeated. It does not write my reflection or tell me how the week went. It shows each project’s current next action and asks what moved. If time runs out, it stops where I stop.

One line per project

The most useful thing on the Home page is a table with one row per active project and one cell that matters: next. Each project keeps exactly one next action, starting with a verb, small enough to start in about ten minutes, specific enough to need no more thought.

The instructions give an example of the difference. “Measure the sunny strip by the fence” is a next action. “Work on the garden” is not. The first one can be started while the kettle boils. The second one gets looked at, feels heavy, and gets put off until Saturday.

Longer plans live in their own notes beside the project. The next action is not a plan. It is the door into one. When I log a win, the agent checks whether it finished the current next action, and if so proposes the following one from the project’s own plan. I say yes or change it. Home is right again.

Exactly one action, starting with a verb, startable in about ten minutes, specific enough to need no more thought.

Missing a week

Systems that depend on a habit die the first time the habit breaks. So the vault has a rule for that, and it is the shortest rule in the manual. If you miss days, or a whole week, don’t try to catch up. Start again with today.

This is not decoration. It shapes the agents too. They are told that missing days are normal and not to comment on gaps. The daily note asks for an energy number from 1 to 5, and on a day marked 1 or 2 the agent suggests one thing to do, not three. It never fills in that number for me. The notes are a record of what happened, not a score.

Sharing without leaking

A second brain is useful because everything goes in. That is exactly what makes it dangerous to share. The case study for this system ended with what was next: a lighter way to share one project’s notes without opening the whole vault. That tool now exists. It is called vault-publish.

The obvious risk is a note with something private in it. The less obvious one is a link. A note you are happy to share links to one you are not, and the title of the private note is right there in the sentence. In the starter vault, the sample project’s hub ends with this line: “The rough costs are worked out in [[Budget scratchpad]], which stays in the vault.” The budget note is not marked for publishing. So vault-publish writes: “The rough costs are worked out in a private note, which stays in the vault.” A link with an alias keeps the alias; one without becomes “a private note”, so the title never leaves. Obsidian comments are removed. Only four properties go out: title, date, tags and description.

Nothing is published by default. Every run needs at least one rule, publish: true in the note, a folder, or a tag, and a note must pass all of the rules given. Only true counts as consent. Then a check reads exactly what would leave, code blocks included, for email addresses, phone numbers, street addresses, card numbers, keys, tokens and any word on a personal deny list. One finding and nothing is written. The report gives the file, line and column, and hides the middle of the match, so the report itself is safe to paste anywhere.

What it does not do

The agents do not think for me. They make sorting cheap, keep the next actions honest and do the counting, but every decision that matters is still a yes or a no from me. That is the design, not a limitation I am waiting to fix.

The privacy check finds the shapes of secrets, not their meaning. It will not notice a sentence about someone’s health, a first name it has never been told, or a photograph. Images are copied, not scanned, and the report lists them so I look. The deny list is how I teach it my own names and places, and the dry run is how I read what would go out before it does. It is a seatbelt, not a reason to stop reading.

And the vault still needs Obsidian to move files safely. Without Obsidian running, the agents hand me a list of moves instead of making them.

The kit

Second Brain OS is open: the folder map, six templates, the Home dashboard, the manual, the agent guide, the eleven skills and vault-publish, with 102 tests and an end-to-end check that runs the tool the way a person would. The sample notes are about a raised bed and the bean-field in Walden. Copy the vault folder, open it in Obsidian, add two plugins, and type /today.
