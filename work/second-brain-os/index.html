Case study · System

Second Brain OS

A low-friction Obsidian system where AI agents capture, sort and review notes so I don’t have to.

Year
2026
Role
Design and build
Status
In daily use
Built with
Obsidian, Markdown, Claude Code skills, Git, TypeScript

Overview

Second Brain OS is a personal knowledge system that runs on plain Markdown files. Anything I capture, from a voice memo to a half-finished thought, lands in a single inbox, and a small group of agents does the sorting and the bookkeeping, asking me before anything moves.

The goal was never a perfect archive. It was to make capturing so cheap that I stop deciding whether something is worth keeping, and to trust that it will be findable later.

The knot

Most note systems fail at the same point: filing takes more effort than the note was worth. For a few weeks it feels fine. Then the inbox grows, the folders stop making sense, and the whole thing is quietly abandoned.

I didn’t want a better filing system. I wanted to stop being the one who files.

My role

This is a one-person project, so I did all of it: the vault structure, the agent instructions, the weekly review and the small scripts that hold it together.

I’m also its only user, which turned out to be the most useful constraint. Anything that added friction got removed within a week.

How it went

Everything goes through one door. There are no folders to choose at capture time, just an inbox, so the moment of writing something down stays as small as it can be.

From there, agents do the housekeeping, but only when I ask. Each is a small skill with one job: capture, sort the inbox, run the weekly review, keep each project’s one next action current. Each proposes before it moves anything, says what it changed, and deletes nothing without a yes, so nothing happens that I can’t see.

Instead of maintaining the system, I review it. Once a week, a twenty-minute review with a timer: empty the inbox, look back, update each project. The agent does the legwork, so the review is mostly saying yes or no.

Where it landed

Capturing now takes seconds, and sorting happens once a week instead of every time I write something down. The part I used to dread has simply gone away.

The kit is now open: the vault structure, six templates, the agent guide and eleven skills, plus vault-publish, a tool that shares chosen notes and refuses to export anything that looks private. It has 102 tests.

Because everything is plain files in Git, nothing is locked in, and any change an agent makes can be reverted.

Decisions I’d defend

Keeping everything as plain Markdown in Git was the decision I’d defend hardest. It means the system can fail in any number of ways and I lose nothing, because every change is a diff I can read and undo.

I also kept the agents small and single-purpose. One agent doing everything is impressive in a demo and impossible to debug at midnight.
